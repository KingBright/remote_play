## 确认并修复

### 桌面来源选择与会话

原界面把第二块显示器写死为 `CaptureSource::Display(2)`。实际 macOS ID 不是显示序号，Windows 安全后端也只公布一个物理主显示源。现通过主机 `ListSources` 枚举真实 ID，Apps 菜单直接列出可用窗口来源；没有第二块显示器就不伪造按钮。窗口与副屏暂不具备输入能力时，显示只读状态，UI 和 ServiceOwner 双层阻止输入。

同一会话的旧 `Subscribed{id}` 回执无法确定属于哪一次切源。新切源消息使用独立 request_id，并核对会话、请求和来源；同时只允许一个在途切换。五秒没有匹配回执便退出待定状态并显示错误，不能因为 UDP 发送成功就认为画面已经切换。超时可能意味着主机已切换但回执丢失，因此暂禁输入，直到下一次切源确认。旧主机不支持新命令时会安全超时，需升级主机后使用该功能。

Host 原实现 abort 后立即启动新任务，且 Windows 会与自己的捕获占用冲突。现在等待旧任务析构完成，回收等待上限两秒；没有回收完成便拒绝新采集。Windows 占用令牌与采集任务共同持有，不会在 FFmpeg 仍存活时提前释放。相同来源仅更新码率等设置，不反复重建。切源保留暂停状态、活动版本、音频活动状态与视频包序号。发送源切换前释放输入，不把按住的鼠标/键盘带到新来源。

### 输入协议

移动 Bridge 原先把左键编码为 1、右键编码为 2，但桌面注入端约定 0/1/2 分别为左/右/中键；测试也沿用了错误预期。本次修正实现与回归测试。

移动端绝对坐标原先发送视频像素，而 Mac/Linux 主机要求完整 u16 归一化范围。Windows 又进行了一次像素换算。现统一为 0..65535；画面中心不论 720p/1080p/4K 都编码为约 32768。补齐触控模式切换时释放拖拽、取消后残留 Up 忽略、慢速双指滚动结束不误触右键，以及 JNI 尺寸转换的上下限。

### 移动手势与桌面工具条

原双指处理吞掉了已有滚动/右键手势，双击还同时影响远端与本地缩放。保留远程双击，只通过 RESET 控件复位；1x 下双指平移归远端滚动，明确捏合后归本地缩放，放大后双指可平移视口。识别待定阶段不发送远程 Move，避免捏合尚未达到阈值就滚动远端；本地手势接管后吞掉错时抬指尾部。跟踪指针对并处理三指、已消费的本地控件事件、窗口尺寸和触控模式改变。触控板模式不被本地缩放倍率降低灵敏度。

桌面只在胶囊和菜单自身建立鼠标遮挡，空白两侧不设置拦截；防止滚轮漏到远端，且只释放本视口实际按下的按钮。负坐标/NaN 不触发顶部感应区。菜单限制高度并可滚动；切源错误自动显露。来源目录使用 Arc 快照，避免每帧复制窗口标题列表。
