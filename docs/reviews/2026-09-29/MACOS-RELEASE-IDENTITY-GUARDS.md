# macOS 授权身份防复发收尾

## 根因与当前现场

Mac Studio 的 TCC 已保存用户授权，但安装包曾因构建机缺少私钥而自动退化为 ad-hoc 签名，不能满足原证书指定要求。原来的完整签名校验只能证明临时签名包未被篡改，不能证明它与被授权版本是同一身份。

Mac Studio 已安装符合原授权身份的正式 alpha.4；本轮再次向实际运行的主机请求 ListSources，鉴权成功并返回 59 项来源，其中包含 1920×1080 显示器。没有启动视频订阅，也没有修改权限数据库。MacBook 仍留在 alpha.1，本轮通过新升级器升级到已发布的 alpha.4，运行进程确认稳定，网络与 launch-agent 配置哈希未变。重复安装同包确认无操作、不重启。

## 已接入的硬性检查

- `deploy/macos/signing-policy.json` 固定原证书公开指纹、bundle ID 和指定要求；不以证书显示名作为唯一依据。
- `scripts/package_macos_unified.sh` 在编译前检查原签名身份；缺私钥直接失败，没有 ad-hoc fallback。发布版本、VERSION 与编译 crate 版本必须一致。
- `scripts/macos_release_guard.py` 验证完整资源签名、原证书身份和稳定指定要求。ZIP 安全解包后重新验证；拒绝路径穿越、符号链接、大小写冲突、特殊文件、过大归档与额外产品包。
- `scripts/publish_desktop_nas.sh` 在任何 scp/ssh 之前检查实际 macOS 包。即便重新计算了正确 SHA-256 的临时签名包，也会被拒绝。
- `scripts/install_macos_unified.py` 默认只生成计划；执行时固定原用户安装路径，验证旧、新两包授权兼容，拒绝回退或同版本不同内容。先验候选，后停止原服务；保存原包，替换后重新验签，核对实际进程和配置。失败恢复旧包。没有权限重置、用户授权自动化或第三方服务管理。
- 根目录 AGENTS.md 和 docs/MACOS_RELEASE.md 明确了后续操作入口和不可降级约束。证书更换必须单独迁移，不能偷偷换一个同名证书。

## UI 修复及状态

共用桌面会话状态增加独立 video_error：捕获/权限错误优先于等待首帧，占用的输入释放并保持锁定，迟到订阅回执不能把失败覆盖为成功；文件清单成功也不能清除视频错误。TCC 提示明确说明“权限可能已开启，需要检查实际运行程序与签名”，不再直接归责于用户没开开关。

UI 改动已写回主仓库，Mac Studio 测试副本与主仓库两个改动文件 SHA-256 一致。该部分没有发布新运行包，也没有覆盖 alpha.4 不可变产物，需随下一版正常签名发布。当前已安装的是此前 NAS 正式 alpha.4，不包含本轮新的提示 UI。

## 已完成验证

- macOS 新发布/升级防护测试：34 项通过，含真实证书签名往返、临时签名替换、签名资源篡改、真实临时签名 ZIP 即便重算摘要仍拒绝发布、服务失败与安装后检查失败的回滚、同包重复无操作。
- 加上已有 Android 发布校验：完整 scripts/tests 共 42 项通过，无跳过的 macOS 原生签名测试；测试只运行编译器与签名工具，没有运行测试 app。
- 桌面 App 库测试：78 项通过，含 3 项新增错误解释测试。
- 桌面 App all-targets 严格 Clippy：通过。
- 实际 MacBook 从 alpha.1 到 alpha.4 的受保护升级成功；重复请求无操作。Mac Studio 既有授权枚举再次成功。
