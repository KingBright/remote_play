# Mac Studio / MacBook 顺序断连切换核查

## 已确认

原先 Relay 把多个设备映射到同一入口并覆盖本地返回地址，导致选定设备与实际画面不一致。该原因已在 alpha.5 的 routed_relay 修复；发现按设备 ID 过滤候选路由，传输绑定源设备、目标设备与连接 token，不兼容旧的裸广播控制路径。过去有真实 Relay 双设备同时订阅的独立窗口像素验证，但不等同顺序 GUI 回归。

本次重新读取：MacBook、Mac Studio 的实际运行包均为 alpha.6 / 20260930.6.10。HO5 启动入口与服务 ExecStart 均指向 alpha.6，当前服务为 inactive、MainPID=0，保留用户退出状态。没有在本次请求中启动或升级应用。

现有桌面代码：候选路由按设备唯一 ID 而非名称筛选；新 Session 新建媒体状态；纹理 ID 包含设备 key 与连接 ID；关闭会话释放输入、停止所属任务；异步返回不会覆盖用户最后的设备选择意图。以上为源码事实，不单独作为实际顺序切换成功的证据。

## 本轮专项测试未执行

准备了 Studio → 关闭 → Book → 关闭 → Studio 的六轮真实 Relay 序列，计划直接调用生产 Desktop::connect / poll / screen / Session::drop，在每轮独立核对目标 ID、连接端点、新连接帧时间以及提交给 GUI 的纹理颜色，并验证迟到连接完成与关闭其他标签的选择行为。只选择唯一名称的合成应用窗口，不订阅桌面、不注入输入。

将测试传到 HO5 并构建测试程序的调用被平台安全检查拒绝，没有执行。两台 Mac 仅编译了限时合成窗口程序，尚未启动。没有本轮 passed 回执。

为避免未验证测试影响现有工程，已撤销本轮添加的 cfg(test) 模块入口，生产 GUI 文件逐字节恢复到开始时状态。测试草案当时尚未编译或集成。2026-10-08确认它基于已退役的 egui 诊断窗口，已从活动源码树退役；原草案留在本机 Git stash 中，仅用于恢复，不是产品源码或验收通过证据。没有通过更换命令或设备继续尝试被拒绝的验收。

## 当前结论

旧 Relay 错投原因已修复且已包含在当前安装版本；不能声称本次“断开一台再连接另一台”的 GUI 路径已经专项真机通过。当前没有新部署、新发布、权限变更或网络身份变更。不要将本记录作为所有时序/所有路由的稳定性保证。
