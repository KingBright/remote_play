# 原生视频扩展：固定依赖、GPU 像素与原控件合成验证

## 当前结论

本轮已真正把固定 GPUI CE 0.3.3 的本地补丁接入 Cargo，并在 Windows cube 的物理 GPU 上完成 NV12、P010 和 BGRA8 三种资源的原生合成验证。随后在实际 GPUI 窗口中同时显示三种生成图案和原版控制胶囊，四个方向轮换，获得正常提交及 GPU 完成记录。

这里的源是人工生成、一次性上传的不可变 GPU 图案，不是远端 HEVC 解码帧。没有因此宣称远端 Windows 端到端视频已完成、零拷贝全链路已成立或所有平台性能最优。Linux 原生导入和实际解码器接入仍未完成，完整版未发布。

## 固定版本与实施范围

使用本机 Cargo 缓存的 gpui-ce-0.3.3.crate，与原 Cargo.lock 中的 SHA-256 核对相等后生成第三方来源清单，共210个上游文件。Cargo.lock 唯一变化是该包从registry切换到固定本地路径，其他依赖版本没有升级。vendor修改范围共12个文件，原许可证完整保留。

`third_party/gpui-ce.UPSTREAM.json` 记录原始来源，`third_party/gpui-ce.PATCH.json` 记录本轮补丁范围和摘要。原生功能由 `gpui-native-video` 显式启用，默认关闭，没有改默认GUI入口。此前被拦截的依赖接入，本轮正常执行成功，没有绕过系统权限。

## 对齐与真实 GPU 验证

共享坐标规则现在覆盖原 ObjectFit 的等比适配、填满裁切、拉伸、只缩不放和保持原始尺寸。D3D呈现也调用这套规则，消除了早期草稿把UI逻辑像素和资源像素类型混用的问题。公共测试18项通过，含4096组旋转/DPI/偏移/裁切布局，其中3571个有效点的采样与输入逆映射一致。

Windows离屏硬件验证采用1920×1088原生资源，绘入128×96验证目标。NV12和P010的四块中性亮度输出为0、255、56、191；BGRA8保留16、235、64、180。遮罩外的背景仍为102/0/102，没有被视频覆盖。另以独立预期象限顺序验证90/180/270度旋转，以及只采样右上象限的crop。

三种格式分别得到计数[1,29,29,1,0,0]，顺序为imports/submitted/GPU_completed/busy/queue_full/rejected。即重复绘制没有逐帧重新导入，29次提交均观察到GPU完成，一次显式的其他设备占锁正确跳过，没有新增提交或无限等待。

最初的忙锁测试错误地在同一个mutex对象上递归获取，收到0x887a0001；修正测试以另一个物理D3D11设备打开共享资源并持有锁后通过。没有将非法返回值当成功、删掉同步保护或跳过失败测试。

这是中性灰度、裁切、旋转和同步检查，不是完整彩色色阶、HDR、显示器色彩校准或扫描输出延迟验证。小目标的CPU读回只存在于验证代码，产品合成路径只映射144字节绘制参数，不读回视频像素。

## 原版控件的实际窗口联调

`native_video_original_window` 在cube上的物理AMD Radeon 8060S上创建真实窗口，三种原生GPU格式并排与原 `stream_status_capsule_card` 组件合成。43次Render调用，三种格式各提交93次，每种资源仍仅导入1次，busy/full/rejected均0，错误为空。窗口结束前GPU完成计数为93/92/92；最后一项可能仍在途，所以这些数字没有被等同为实际呈现帧数或帧率。

真实窗口测试暴露了原控件把CSS泛称monospace直接当DirectWrite字体名称的问题。测试构建严格拒绝缺失字体；本轮没有安装或复制字体，也没有改成比例字体掩盖问题。根使用GPUI的原生系统字体选择器，原胶囊数值区域在Windows解析到已经安装并检查存在的Consolas，其他平台保持原表达。控制胶囊结构、颜色和交互设计未重做。

这只是带原组件的开发验证窗口，不是可供用户替代完整产品的三格测试UI。没有将它发布到NAS或设置为默认入口。
