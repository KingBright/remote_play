这次更新

桌面端在鼠标按下时立即取得焦点，防止拖拽中途触发 ReleaseInput 并吞掉松开事件；GUI 和无界面启动共用同一 profile 的实例锁，避免端口与 Relay 身份冲突；失效会话不再复用，并提供 Reconnect selected device。手机发行版本同步到 alpha.7，versionCode 为 8。

已有设备

本轮直接部署目标为 HO5、MacBook、Mac Studio 和 Windows cube。HO5 的应用菜单与 ~/.local/bin/remoteplay 指向新版本。两台 Mac 使用原用户目录 ~/Applications/RemotePlay.app，并沿用原授权签名。Windows 提供桌面与开始菜单 RemotePlay 入口，默认只观看，不启用本机捕获或自启动。保留原有设备网络身份，不需要重新入网。

Android 使用原发布签名，可以覆盖安装。实体手机没有连接到部署通道时，需要在手机下载 APK 并确认安装；上传 NAS 不等于手机已升级。不要先卸载旧应用，以免丢失本地身份。

使用顺序

  1. 从设备列表选择具体 Mac 的 View / Control。画面出现后，点击 Enable control，再点击远端画面获取键盘焦点。
  2. 测试点击、按住拖动、松开以及输入。Ctrl+Alt+Esc 可锁定远端控制。只读、暂停、失焦和失联状态仍保留保护。
  3. 切换设备时关闭旧标签或点击对应设备。连接异常使用 Reconnect selected device；新连接默认仍锁定输入。
  4. Applications / Application windows 中选择真实窗口。窗口级操作使用主机前台焦点，不是隐藏窗口的独立后台桌面。该主机适配目前在 macOS 实现，其他平台作为观看端复用同一协议。

验证范围

Linux、macOS、Windows 已运行各自的相关库测试，并单独运行生产 GUI 鼠标/键盘事件至本地协议记录器的回归，覆盖 Down、Up、KeyDown、KeyUp。macOS Release 沿用固定证书并经过签名与升级校验；Windows GUI 启动检查不启动本机捕获。Android Release、Lint、签名、JNI 与原生库对齐校验通过，JVM 单测结果有缓存复用。

短时拉流、构建和协议记录器验证不是所有真实应用、所有网络、长时间稳定性的保证；不要把本次部署当作 Windows/UU 并发捕获或实体手机交互已经全面验收。Mac 包为现有本地证书签名，未做 Apple 公证。
