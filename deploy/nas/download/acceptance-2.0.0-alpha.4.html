返回下载页 · 三个桌面平台共用 GUI，四个平台共用 Rust 互联与文件协议。

HO5 使用入口

应用菜单搜索 RemotePlay，或运行用户目录中的 ~/.local/bin/remoteplay。关闭窗口保留后台网络；再次打开会唤回现有窗口。真正退出请点 Quit RemotePlay。不要同时手工运行另一份程序。

在左侧选设备：View / Control 主动拉取画面，Files 直接进入文件交换，不要求开启视频。Publish selected files 只共享明确选中的文件，对方刷新后可 Pull to this device；只读来源不会开启输入。新会话默认锁定输入，确认画面正确后再解除 Input locked。

共有网络无需重建或逐台配对。文件默认保存到 ~/Downloads/RemotePlay。当前只浏览明确共享的文件，不提供任意远端目录访问。

按平台安装

Linux：包内为真正桌面 GUI + 主机程序，不再是 host-only。为 HO5/Bazzite x86_64 构建，依赖系统 FFmpeg、ALSA、OpenGL、桌面会话等，不承诺同一二进制可运行于所有旧发行版。不要把测试用配置覆盖现有 mesh 目录。

macOS Apple Silicon：桌面端默认也使用共用 GUI；旧 GPUI 界面仅为兼容入口。包使用本地签名、未做 Apple 公证。更新时先退出原实例；保持应用路径和权限，不删除原设备网络。

Windows：包含同套 GUI 和私有 FFmpeg 解码器。默认只作为观看/主动文件操作端，不启动本机捕获、不启用自启动。主动查看别的设备不等于已通过 Windows 被控捕获或与 UU 同时串流验收。

Android：正式签名 ARM64 APK，可覆盖升级；不要先卸载。Compose/MediaCodec 保留系统适配，互联、鉴权和文件传输复用同一 Rust 核心。虚拟键盘不等于完整 Unicode 输入；远程控制 Android 自身受系统权限与现有实现限制。

已执行的验证与边界

Linux 和 Windows 的真实 GUI 均完成了合成文件的列表请求、主动取回、512 KiB 落盘和逐字节/哈希核验。测试文件经鉴权回环连接传输，不冒充跨公网大文件压力测试。共用桌面 App、Client、Bridge 已执行目标单测，Linux/Windows 的 HEVC 解码测试使用真实 FFmpeg 与合成视频，不采集本机桌面。

本轮 HO5 向 MacBook 发起实际画面连接，鉴权成功并使用 Relay，但 MacBook 的系统屏幕捕捉权限返回拒绝，未得到新画面。因此当前真实屏幕拉取不能写成“已通过”。MacBook 需要由用户在系统设置的隐私与安全性中正常授权屏幕录制；不能用修改 TCC 数据库或关闭安全机制代替。

Android 实体手机的 SurfaceView 变换、触点和横竖屏仍需实机验收；此前模拟器 ANR 不算通过。Windows 文件 GUI 测试未启动屏幕捕获，测试后 UU 服务仍运行，进程未被替换。

建议验收顺序

  1. 先正常授权 Mac 主机屏幕录制，再由 HO5 点 View / Control，检查首帧、声音和解锁输入。
  2. 同一设备切屏或切窗口，核对真正来源；在暂停、切后台、显示旧帧和对话框期间不得误发输入。
  3. 两端分别 Publish、Refresh、Pull，检查文件内容与保存位置；再测取消、翻页、连接断开后重新打开。
  4. Android 覆盖升级后检查原网络、捏合与点击、双指滚动、暂停和组合键。各项失败请记录两端版本、连接路径和实际错误提示。
